Unlocking Ampere: Hardware-Software Co-Design

This project moves beyond naive porting. By deeply understanding the DGX A100's HBM2e memory system and the specific capabilities of the Ampere Architecture, we implemented a co-design strategy.

The goal was not just "faster code," but code that naturally fits the hardware, exploiting architectural features to realize the GPU's true potential.

Three Major CUDA Kernel Innovations

Scroll to explore the architectural optimizations.

01

Asynchronous Copy

cp.async

We implemented cp.async to create a direct, non-blocking path from Global Memory to Shared Memory.

Animation: Watch the data packets move. This instruction allows the CUDA cores to continue computing while data is being fetched, effectively hiding the massive latency of HBM2e access.

02

L2 Cache Persistence

cudaAccessPropertyPersisting

The A100 features a massive 40MB L2 Cache. We tuned the access properties to mark critical data as "persisting".

Visual: The L2 Cache block glows green. This ensures frequently used data stays "hot" in the cache, preventing it from being evicted and reducing costly trips back to Global Memory.

03

Optimized Tiling

Shared Memory Tiling

Leveraging the Ampere SM's increased 164KB Shared Memory capacity, we redesigned our data tiles.

Visual: The Shared Memory block expands and shows a dense tiling pattern. Larger tiles mean more data reuse and fewer global memory transactions, pushing performance closer to the compute roof.
